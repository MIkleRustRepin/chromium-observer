# Chromium Observer

Локальный форк Chromium для наблюдения за своим ИИ-агентом: JPEG видимой области активной вкладки по UDP раз в секунду, обычный интерфейс браузера, сервер с последним кадром в памяти.

**Статус: разработка.** Сервер и просмотрщик проверены. Пользователь подтвердил работу Mac-версии с UDP. Собственная Linux-сборка ещё не завершена; готовых бинарных релизов пока нет.

Исходная версия и commit закреплены в `upstream.json`. Полный checkout загружается в `chromium/src`, изменения для воспроизводимости хранятся в `patches/observer.patch`, а читаемая копия нативного кода — в `native/`. Базовые исходники Chromium и артефакты сборки не включены в этот репозиторий. Уведомление о лицензии Chromium сохранено в `LICENSE.chromium`.

```bash
git clone https://github.com/MIkleRustRepin/chromium-observer.git
cd chromium-observer
```

## Сборка Linux

Нужны Python 3.10+, Git, зависимости Chromium и достаточно места на диске. Первичная загрузка и сборка занимают значительное время. Скрипт сборки запускает два задания и останавливает собственный процесс при остатке диска меньше 5 ГиБ; чужие файлы не удаляет.

```bash
python3 scripts/bootstrap.py
cd chromium/src
sudo ./build/install-build-deps.sh --no-prompt --no-arm --no-chromeos-fonts
export PATH="$PWD/../../tools/depot_tools:$PATH"
export DEPOT_TOOLS_UPDATE=0
gclient runhooks
cd ../..
python3 scripts/apply_patch.py
python3 scripts/build.py
python3 scripts/package.py
```

На Linux, если выше каталога Chromium есть `node_modules`, скрипт сборки скрывает их только от своего процесса через `bubblewrap` (`sudo apt install bubblewrap`). Это предотвращает подхватывание домашних пакетов TypeScript; файлы на хосте сохраняются.

## Локальный запуск

В одном терминале:

```bash
python3 -m server.server
```

По умолчанию HTTP-просмотрщик слушает `0.0.0.0:8765`, UDP-приёмник — `0.0.0.0:8766`: они доступны через внешний IP сервера. Для запуска только на localhost:

```bash
python3 -m server.server --host 127.0.0.1 --udp-host 127.0.0.1
```

В другом:

```bash
chromium/src/out/Observer/chrome --user-data-dir="$PWD/artifacts/agent-profile"
```

Открыть **http://127.0.0.1:8765/** в отдельном обычном браузере. При локальном просмотре расположить окна рядом, чтобы наблюдаемая вкладка оставалась видимой. Использовать выделенный профиль наблюдаемого Chromium, чтобы запущенный системный браузер не перехватил запуск. Захват запускается автоматически без дополнительных переключателей.

Проверочная страница: `file:///абсолютный/путь/к/проекту/scripts/test-page.html`. Она показывает часы, анимацию и область для прокрутки.

## macOS Apple Silicon

Установить **полную Xcode** из Mac App Store и открыть её один раз, чтобы принять лицензию и установить компоненты. Затем на Mac Studio / Mini с Apple Silicon запустить:

```bash
./build-mac.sh
```

Скрипт сам скачает закреплённые Chromium, `depot_tools`, зависимости и Python для сборки, выполнит hooks, применит патч, соберёт `Chromium.app` для arm64 и создаст `artifacts/chromium-observer-macos-arm64.tar.gz`. По умолчанию кадры уменьшаются до **0.75 по ширине и высоте** от исходного рендера. Homebrew не нужен. Начальный запуск использует Python 3.9+ из Xcode command-line tools; дальнейшие этапы — закреплённый Python из `depot_tools`.

Можно скачать только консольный скрипт — он сам клонирует этот проект в `~/chromium-observer`:

```bash
curl -fL https://raw.githubusercontent.com/MIkleRustRepin/chromium-observer/main/build-mac.sh -o /tmp/chromium-observer-build-mac.sh
bash /tmp/chromium-observer-build-mac.sh
```

Нужны APFS и минимум 100 ГиБ свободного диска для первого запуска; рекомендуется 150 ГиБ и больше. Путь к проекту должен быть без пробелов. Число заданий выбирается по RAM/CPU; Mac не уходит в сон во время работы. Повторный запуск использует скачанные файлы и результаты компиляции. Логи сохраняются в `logs/build-mac-*.log`.

```bash
./build-mac.sh --jobs 4
./build-mac.sh --endpoint udp://127.0.0.1:8766
./build-mac.sh --scale 0.5  # половина исходной ширины и высоты
./build-mac.sh --scale 1.0  # исходное разрешение
./build-mac.sh --clean  # пересоздать только артефакты out/Observer
```

Для другого каталога при запуске отдельного скачанного скрипта задать `CHROMIUM_OBSERVER_DIR`. При нестандартном расположении Xcode можно задать `DEVELOPER_DIR`. `--tests` дополнительно собирает browser tests; автоматически они не запускаются.

Для обновления уже собранной версии выполнить `git pull --ff-only`, затем `./build-mac.sh`. Скрипт обновит предыдущую версию нашего патча и переиспользует готовые файлы сборки. Если исходники патча изменены вручную, обновление остановится с диагностикой Git, сохранив эти изменения.

Запускать `chromium/src/out/Observer/Chromium.app/Contents/MacOS/Chromium` с отдельным `--user-data-dir`. Сервер: `tools/depot_tools/python-bin/python3 -m server.server`. Архив содержит локальную сборку; подпись Developer ID и notarization в задачу не входят. Новый UDP-транспорт ещё не проверен на Mac.

## Поведение и настройки

- Выбирается активная вкладка последнего активного открытого окна Chromium. Окна инкогнито исключены. Если выбранное окно свёрнуто или поверхность недоступна, новый кадр не отправляется.
- Передаётся viewport страницы, JPEG quality 80. `--scale` задаёт долю ширины и высоты от пикселей рендера с учётом Retina: например, 2560×1440 при `0.75` превращается в 1920×1080, при `0.5` — в 1280×720. Размер округляется до ближайшего целого, минимум 1×1. Масштаб меняет только передаваемый кадр. Панели браузера, системные диалоги и курсор ОС в кадр не входят. Защищённое содержимое подчиняется ограничениям Chromium.
- Период — 1000 мс; тайм-аут захвата — 500 мс, отправки — 2 секунды. Выполняется только один цикл; при задержках кадры пропускаются без очереди.
- Для прямого вызова Python-сборщика: `python3 scripts/build.py --scale 0.75`. Его значение по умолчанию — `1.0`; Mac-скрипт передаёт `0.75`. Допустимы конечные значения `0 < scale <= 1`. GN-параметр для ручной настройки: `page_frame_stream_scale = "0.75"` (строка, поскольку GN не поддерживает дробные числа).
- Сервер хранит только последний JPEG в RAM. После перезапуска история отсутствует. В просмотрщике кадр старше трёх секунд помечается как устаревший.
- Endpoint задаётся при сборке: `python3 scripts/build.py --endpoint udp://127.0.0.1:8766`. Поддерживаются числовые IPv4 и IPv6 (`udp://[::1]:8766`). Порт приёмника задаётся через `--udp-port`, порт HTTP-просмотрщика — через `--port`.
- JPEG разбивается на UDP-датаграммы до 1200 байт: номера фрагментов, UUID сессии, номер кадра, время захвата, полный размер и CRC32. Потерянный или повреждённый кадр пропускается без повторной передачи. Приёмник держит до двух неполных кадров и удаляет их через 3 секунды. Нативный отправитель ограничивает отправку кадра двумя секундами и выдаёт до четырёх пакетов за миллисекунду. Формат описан в `UDP_PROTOCOL.md`.
- Обычный внешний вид не означает необнаружимость: изменения бинарника и сетевые соединения можно исследовать средствами ОС.

## Проверки

```bash
python3 -m unittest server.test_server server.test_udp -v
python3 -m unittest discover -s scripts -p 'test_*.py' -v
node scripts/test_viewer.cjs
```

Вторая команда требует установленный пакет `playwright` и Chrome; путь к бинарнику можно задать через `TEST_BROWSER`. Она проверяет сервер и просмотрщик, а не нативный захват.

Нативные проверки и фактический статус сборки описываются в `VALIDATION.md`.

API просмотрщика: `GET /api/frame` отдаёт последний JPEG и метаданные в заголовках, до первого кадра — `204`. `GET /api/status` отдаёт JSON с метаданными. Для всех ответов отключено кеширование. Загрузка кадров через HTTP отключена (`POST` возвращает `405`); браузер передаёт кадры только по UDP.

## Сервер с публичным IP

На сервере остановить старый приёмник, обновить репозиторий и запустить UDP-приёмник на внешнем IPv4-интерфейсе:

```bash
git pull --ff-only
python3 -m server.server
```

На Mac обновить репозиторий и пересобрать с адресом сервера (подставить настоящий IP):

```bash
git pull --ff-only
./build-mac.sh --endpoint udp://SERVER_PUBLIC_IP:8766
```

Mac-скрипт сохраняет масштаб `0.75`; для обновления с HTTP-версии патч заменяется автоматически. Разрешить входящие UDP на порт 8766 и TCP на порт 8765. COU1 передаёт JPEG без шифрования и аутентификации; HTTP-просмотрщик доступен без пароля. Для публичного сервера ограничить источники файрволом либо использовать защищённую приватную сеть.

Просмотрщик открывается напрямую по **`http://SERVER_PUBLIC_IP:8765/`**; также можно использовать домен сервера. Для просмотра только через SSH запустить HTTP-часть с `--host 127.0.0.1` и открыть туннель:

```bash
ssh -N -L 127.0.0.1:8765:127.0.0.1:8765 user@SERVER_PUBLIC_IP
```

С туннелем открыть `http://127.0.0.1:8765/`. Этот TCP-туннель служит просмотрщику; кадры Chromium идут напрямую по UDP на порт 8766. Адрес HTTP-привязки меняется через `--host`, UDP-привязки — через `--udp-host`.

Для проверки приёмника отдельным JPEG без Chromium:

```bash
python3 -m server.send_frame --host 127.0.0.1 --port 8766 < frame.jpg
```
