# Проверка Chromium Observer

## Среда

- Ubuntu 25.10, x86_64, около 15 ГиБ RAM.
- Swap: суммарно 10 ГиБ; настройка проверена после перезапуска системы.
- Исходная ревизия Chromium: `5869fe313571d75152b77813cf0a4ee26a4e6df0`, версия `155.0.8059.84`.

## Выполнено

- `python3 -m unittest server.test_server server.test_udp -v`: 11 тестов пройдено. Проверены настоящий UDP-приём по IPv4/IPv6, сборка фрагментов в произвольном порядке, дубликаты, потеря пакета, CRC32, неверные заголовки, лимит памяти, тайм-аут, старые кадры и сессии, перезапуск UDP-порта, HTTP-просмотр и отказ от HTTP-загрузки.
- `node scripts/test_viewer.cjs`: пройдено в установленном Google Chrome. Проверены декодирование настоящего JPEG, размер 900×600, устаревание кадра и восстановление. Кадры в этом запуске передаются по UDP; задержка — 682 мс. Это проверка сервера и просмотрщика, а не нативного сервиса.
- `python3 scripts/apply_patch.py`: обнаруживает уже применённый патч без повторного изменения файлов.
- Системные зависимости Chromium установлены через upstream `install-build-deps.py`; для Ubuntu 25.10 использован `--unsupported`.
- Синхронизация зависимостей и `gclient runhooks`: успешно.
- GN generation: успешно, 35 981 targets из 5066 файлов.
- `gn check out/Observer '//chrome/browser/observer:*'`: Header dependency check OK.
- `gn format --dry-run` и `clang-format --dry-run --Werror` для новых C++-файлов: успешно.
- `bash -n build-mac.sh`: успешно.
- `python3 -m unittest discover -s scripts -p test_build_mac.py -v`: 6 тестов пройдено. На подставных macOS-инструментах проверены загрузка проекта отдельным скриптом, порядок этапов, выбор числа заданий, передача параметров, масштаб по умолчанию `0.75`, выбор `0.5`, отклонение неверного масштаба до скачивания, очистка артефактов и остановка/повторный запуск после ошибки, отказ от HTTP-endpoint и передача IPv6 UDP-адреса. Это проверка скрипта, а не настоящая macOS-сборка.
- Разрешение типов DevTools изолировано от родительских `node_modules`: типовой импорт Puppeteer Replay направлен на классы, поставляемые в Chromium. Конфликт с домашним Puppeteer 24.43.1 воспроизведён через `--traceResolution`; после изоляции та же TypeScript-компиляция Recorder проходит. Три теста проверяют путь, повторный запуск и сохранность существующих зависимостей.
- Linux-сборка скрывает родительские `node_modules` через отдельное пространство монтирования `bubblewrap`. TypeScript-компиляция WebUI ESLint проходит без домашнего `buffer`. Три теста изоляции включают настоящий запуск дочернего процесса с `/dev/null`, сохранность пакетов хоста и доступность зависимостей внутри checkout.
- До добавления масштаба: `python3 scripts/build.py --jobs 4 --target obj/chrome/browser/observer/observer/page_frame_streamer.o` успешно скомпилировал модуль захвата Clang из закреплённого Chromium. Это ещё не сборка и запуск исполняемого браузера.
- `python3 -m unittest discover -s scripts -p 'test_*.py' -v`: все 20 тестов скриптов пройдены. Включены обновление патча, откат при ошибке, сохранность пользовательских изменений и передача `--scale` в GN без запуска компилятора Chromium. Отдельный C++20-тест компилирует настоящий `native/udp_frame_protocol.h`, проверяет побайтовую совместимость пакетов с Python и сборку этих пакетов приёмником.
- `python3 scripts/build.py --scale 0.75 --generate-only` и последующий `gn check`: успешно.
- Новый код UDP-отправителя и захвата проверен `Clang -fsyntax-only` с флагами из сгенерированного Ninja для масштабов `0.75`, `0.5` и `1.0`: успешно. Объектные файлы при этой проверке не создавались.
- Переход с обоих HTTP-патчей (`observer-v1.patch`, `observer-v2-scale.patch`) на текущий UDP-патч проверен на временной копии настоящих исходных файлов закреплённого Chromium. Полученные файлы совпадают с `native/`; повторное применение идемпотентно.

## Ещё не подтверждено

Полная Linux-сборка остановлена по просьбе пользователя. Ошибки TypeScript из-за домашних зависимостей устранены. Нативные тесты ещё не запускались; готовый Linux-бинарник отсутствует. UDP-отправитель внутри запущенного Chromium ещё не проверен; тест просмотрщика использует настоящий JPEG, отправленный диагностическим Python-клиентом.

После сборки:

```bash
python3 scripts/build.py --tests
chromium/src/out/Observer/browser_tests --gtest_filter='PageFrameStreamerBrowserTest.*' --test-launcher-jobs=1
xvfb-run -a node scripts/test_native.cjs
python3 scripts/package.py
```

На Linux browser tests также запускать с виртуальным дисплеем, если обычный дисплей не используется. Сквозной тест требует Playwright, Python Pillow и openbox. Он использует обычный профиль, поскольку вкладки инкогнито исключены из захвата.

Для бинарника, собранного с `--scale 0.75`, передавать соответствующее ожидание сквозному тесту: `TEST_FRAME_SCALE=0.75 xvfb-run -a node scripts/test_native.cjs`. Browser tests получают масштаб из GN автоматически.

Сквозной тест сохраняет результаты в `artifacts/native-validation.json` и последний настоящий кадр в `artifacts/native-last-frame.jpg`.

macOS arm64: пользователь сообщил об успешной сборке предыдущей версии. Версия с UDP ещё не проверялась на Mac.
